ER schema JSON

ER schema JSON guide

Use this format in the editor or ER Mapper. Optional flags can be left out when they are false.

{
  "entities": [
    {
      "name": "Employee",
      "attributes": [
        { "name": "EmployeeID", "isPrimaryKey": true },
        { "name": "Name" },
        { "name": "Contact", "composite": ["Email", "Phone"] }
      ]
    },
    {
      "name": "Department",
      "attributes": [
        { "name": "DepartmentID", "isPrimaryKey": true },
        { "name": "Name" }
      ]
    }
  ],
  "relationships": [
    {
      "name": "WorksFor",
      "participantEntities": [
        { "entityName": "Employee", "cardinality": "N", "participation": "total" },
        { "entityName": "Department", "cardinality": "1", "participation": "partial" }
      ],
      "attributes": [{ "name": "StartDate" }]
    }
  ]
}
  • Each entity needs a name and an attributes array. Give regular entities a primary key with "isPrimaryKey": true.
  • Attribute flags are isPrimaryKey, isMultiValued, and isDerived. A composite list can contain names or nested attribute objects.
  • Weak entities use "isWeak": true and a non-empty partialKey list.
  • Relationships need a name and participantEntities. Each participant has an entityName, a cardinality such as 1 or N, and total or partial participation.
  • Set "isIdentifying": true for an identifying relationship; it must connect at least two participants. Relationship attributes are optional.

ER schema JSON

ER schema JSON guide

The Mapper accepts the same ER schema format produced by the ERD Generator. Paste it here or load a .json file.

{
  "entities": [
    {
      "name": "Employee",
      "attributes": [
        { "name": "EmployeeID", "isPrimaryKey": true },
        { "name": "Name" }
      ]
    }
  ],
  "relationships": []
}
  • The top level must contain entities and relationships arrays.
  • Each entity needs a name and attributes array. Include a primary key for regular entities.
  • For weak entities, set isWeak to true and provide a non-empty partialKey array.
  • Relationship participants refer to entities by name and include cardinality and participation (total or partial).
